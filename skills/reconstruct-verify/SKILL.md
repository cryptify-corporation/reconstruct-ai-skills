# Verify a reconstructed interface

Verify the requested component, page or flow. Maintain separate conclusions for capture coverage, implementation coverage, visual fidelity and functional behavior. Do not collapse them into an unsupported percentage or call a screenshot match functional equivalence.

Discover the client's available browser/native observation tools, including connected MCP tools, before declaring runtime verification unavailable. A CLI may receive real preview screenshots and rendered measurements through a separate authorized CUA tool even when it has no built-in browser. Use that capability within its documented target and viewport limits; never substitute source inspection for a returned runtime observation. When the connected tool offers reference comparison, pin its reference to the current downloaded Scene and exact frame, and execute that comparison for each claimed measured state. A returned comparison of unverified is not a fidelity pass. Retain unmatched nodes and state/scroll/profile mismatches as unverified rather than replacing them with an impression from a screenshot.

## Verify semantic behavior

Read the selected page intent and relevant named flow. For each primary action record the rendered control, expected outcome, actual preview outcome and evidence; never mark `unknown` or `performedUnverified` as a successful observation. Walk each relevant flow branch and preserve failed, paused or missing segments. Exercise controls/filters and confirm that related regions update from shared state. For dynamic lists verify at least an item/state change in the local implementation. Keep observed-fidelity checks separate from inferred expectations and operator requirements. Report tested/total action and flow-step counts, unverified relationships and missing mappings. A checklist or generated requirement is not execution evidence; missing test results stay unverified. Do not claim semantic coverage from a visual screenshot or from static source inspection alone.

## Establish the comparison

Pin the reference capture selection and the local implementation revision. When advertised, obtain the canonical `reconstruct.scene.v1` export through `get_interface_scene`; select the exact profile/state/frame and preserve its logical coordinate space, truncation, issues and measured/declared/inferred fact provenance. Unknown or unsupported properties are not implicit zeros, false values or successful comparisons. Native DOM/CSS, Android layouts and accessibility trees are optional diagnostic evidence, not an alternative canonical contract. Do not claim an export, adapter or renderer is ready from the schema name alone. Obtain only relevant scenario manifests, steps and image/artifact references through available MCP tools. Read current schemas and retain exact view keys. A recorded replay validates behavior in the captured environment; it is not an executable test of the new implementation.

Match viewport, theme, locale, data shape and application state. For native Android also match recorded density, font scale and safe insets; missing values are explicit comparison gaps. Keep native screen and WebView viewport coordinate planes separate unless their mapping is recorded. A page reproduction normally requires desktop, mobile and an intermediate width, with top, middle and footer inspected. Wait for fonts/images and confirm the intended font files actually loaded before judging line wraps. Check horizontal overflow, collisions, clipping, content order and responsive navigation. A screenshot scaffold or fixed clipped iframe layout is not a responsive page. Record mismatches that prevent a meaningful comparison. Check source truncation and starter limitations before declaring a missing element an implementation defect.

For Web-specific supplemental evidence, use measured references where they exist: state screenshots from `stateCatalog.screenshots`, revealed menus from `reveals`, `themeScreenshots` for the alternate scheme and `viewportVariants` for extra widths, all through `get_page_evidence_image`. Element `volatile` and `evidence.volatileRegions` mark carousels, live regions, autoplay media, looping animation and observed mutations; exclude them from image diffs or freeze them deliberately. A recorded scenario step's `network` gives the expected request outcome by method, path pattern and status.

## Exercise behavior

Derive happy-path assertions from observed actions and outcomes. A Scene action or recorded request is not proof of success. Check the transition's source/destination frames and distinguish changed, unchanged, failed, unknown and performed-unverified; test the corresponding action independently in the rebuilt application. Use explicit node correspondences rather than assuming Android tree-path identity across snapshots. Add edge cases relevant to the change, such as double submission, refresh, expired sessions or cross-user access, rather than running every possible case for every task. Test the new implementation against local or authorized test environments. Exercise visible navigation, filters, menus and keyboard/focus states where relevant. Verify motion triggers, timing and final visibility, and test reduced-motion behavior; a still screenshot cannot prove animation works. Do not fuzz or load-test a reference product.

Reuse the project's test framework and fixtures. For browser tests, prefer roles and accessible labels over brittle source CSS selectors; captured `a11y` with `source: chromium` gives the reference role and name. Check console errors and failed requests with context, distinguishing expected negative cases and unrelated third-party failures from defects. Apply accessibility checks to changed screens and manually inspect behavior automation cannot establish.

## Compare and fix

Use deterministic image comparisons when appropriate, with explicit tolerances and dynamic-region exclusions. Inspect geometry, typography and clipping separately from color differences that are intentional. Compare layout constraints separately from visual bounds; observed pixel positions do not prove a fixed layout. Keep declared/inferred properties out of the measured-fidelity pass count, and report unsupported Scene fields or unresolved platform mappings explicitly. For every checked profile compare visible asset identity/count (including full-logo versus compact-mark alternatives and hidden ancestors), measured font size/line-height/letter-spacing and resulting line wraps, plus recorded spacing and shadows. Trace an opened menu or popover to revealed-state evidence; report any inferred structure separately instead of passing it as a faithful match. Grid edge-density scores are coarse diagnostics, not fidelity metrics. Requirements-matrix completion is implementation status, not independent proof that a feature works.

Report only reproduced bugs as confirmed. Use [the verification template](assets/verification.md) to record steps, expected/actual behavior, evidence and severity. Put untested concerns in a separate list. Fix authorized defects, retain meaningful regression checks and rerun affected tests. Broaden testing when dependencies or failures justify it; avoid rerunning unrelated suites after every cosmetic adjustment.

Deliver checks run, results, reproduced defects, intentional differences and unverified areas. A blocked core flow, data loss, incorrect billing or broken authorization prevents readiness for that scope. Do not assert production readiness from a limited visual check.


For overlays and disclosures, inspect the Scene's `entryFrameId`, all relevant state frames and transitions before implementing behavior. The entry frame may show consent while `default` is the later dismissed state. Preserve each frame's `viewportBounds` and coordinate space, full backdrop/panel geometry, clipping, stacking, underlying content and `semantics.modal`/`expanded` observations. Use a transition's trigger node in its own source frame; repeated node IDs across frames are not identity. Reproduce and visually check the observed open and closed states at each measured profile. A successful click or icon replacement with `performedUnverified` does not establish that a panel opened; missing modal evidence is an explicit capture gap, not permission to invent its design.


For each checked profile and observed open overlay, record expected-versus-rendered bounds for the surface and its visible controls, not only the outer rectangle. Include internal row/column arrangement, label line wraps, dividers, shadows, clipping and action reachability. An outer size match cannot pass a surface whose children are misplaced or clipped. Use stable node-to-renderer mappings where available and state the matching method and tolerance. When a comparison tool accepts explicit source-node/selector pairs, supply them for unnamed surfaces, media and controls that automatic label matching cannot resolve. Choose the correspondences from the pinned frame and actual rendered hierarchy; a missing or ambiguous mapping remains unverified. Fix reproduced mismatches before marking that state passed; keep unmeasured properties outside the pass count.
